LOST PHONE FINDER — FEATURE LIST (from zero to now, 11 Oct 2026)

APP BASICS
--------------------------------------------------------------------------------
1. Email/password registration and login (Firebase Auth, persistent sessions).
2. My Devices list, real-time from Firestore.
3. Add this device (name, model, owner phone for SMS fallback).
4. Device detail screen per phone.
5. Fleet map showing every tracked device.
6. Expo Router navigation (Login/Register/Devices/Device/Map/Mesh).
7. EAS project linked (@saikat_03/lost-phone-finder); Android dev builds.
8. Firebase project wired (Auth + Firestore + owner-only security rules).

LOCATION TRACKING (Phase 2) — TESTED ON DEVICE
--------------------------------------------------------------------------------
9.  One-tap "Send location now".
10. Background GPS every 10 min / 50 m (foreground-service notification).
11. Foreground fallback tracker for environments without background support.
12. Battery % captured with every fix.
13. Location history (last 50 fixes) per device.
14. Live map with latest (red) + history (blue) pins; interactive pan/zoom.
15. Map layers: Satellite (default, Esri World Imagery — street rasters are blank
    in rural India), Streets (OpenStreetMap), Terrain, plus an optional place-name
    overlay. Accuracy circle per fix, popup with accuracy + fix age, ◎ re-centre
    button, scale bar. All keyless (no Google billing). Fixes are GPS-quality
    (Accuracy.High); the device screen shows ±accuracy and warns when the newest
    fix is more than 3 minutes old.
SIM-SWAP & THEFT ALERTS (Phase 3) — TESTED ON DEVICE
--------------------------------------------------------------------------------
16. SIM baseline snapshot at registration (carrier + MCC/MNC + ISO).
17. Automatic swap check on every background batch + manual "Check SIM now".
18. Swap flips device to simSwapped + LOST and fires an on-device alert.
19. Manual Mark-LOST / Clear-LOST emergency toggle.
20. SMS-owner-location composer with prefilled Google Maps link + battery.
21. Devices list shows SIM/LOST state live.
    (Limits, stated honestly: true IMSI reads are impossible for store apps —
     same-operator SIM swaps may not trip detection; SMS needs one user tap.)

OFFLINE MESH (Phase 4a + 4b)
--------------------------------------------------------------------------------
22. NaCl sealed location packets — helpers relay opaque blobs they can't read.
23. Per-device mesh keypairs (SecureStore + owner-only backup, pubkey on device).
24. SQLite store-and-forward queue (24h TTL, 200 cap, memory fallback).
25. Gateway relay upload + owner harvest/decrypt into device history.
26. Mesh screen: device picker, one-tap cloud relay test, harvest, live queue.
27. Helper BLE scan role (find -> connect -> read packet -> relay). VERIFIED.
28. Phone-as-beacon role via custom native advertiser module (BluetoothLeAdvertiser
    + GATT server, helper-connected/packet-read events). VERIFIED end-to-end on
    2 phones 19 Oct 2026: beacon -> helper read -> relay -> harvest "5/5 decrypted".
    Cross-account proof the same night: the OPPO (different account) read the
    Samsung's fresh packet 5x and relayed it; its own harvest found 0 (it cannot
    read what it relays), while the Samsung harvested 5/5 and got the positions
    in its history. The beacon also works with no GPS fix (advertises with an
    empty position rather than refusing to start).
29. Radio diagnostics: "Radio check" lists every nearby BLE device; scan result
    alerts report heard/connected/read counts plus a per-step trace; the beacon
    status line shows the real advertising state (or the failure code).
    (Proven: cloud relay loop "Checked 1, decrypted 1". Radio test needs the
    4b build on 2 phones, Bluetooth on, ~10 m apart, stolen phone offline.)
